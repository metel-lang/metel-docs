### F01 — Missing generic closure capture escapes the definition check

The following program declares both the negative row condition and the all-Copy
condition. Initial expected outcome was that the assertions would succeed (9 and
11). Investigation found that the explicit `[copy]` list also needs `id`, so the
program must instead be rejected at its definition with `T0026` under
`spec.functions.closures.legality-7`. Actual at the session baseline, both default mode
and `--move-check`: `I0010`, generic definition `copied_tail` and construction
disagree. The equivalent program with the closure body directly in
`copied_tail` succeeds. A simple all-Copy row capture without the transition
also succeeds. Correcting the list to `[copy, id]` succeeds without move checking;
with move checking it encounters the separate destructuring failure tracked by
#1407. The callback alias also exercises previously released written function
types and transparent aliases.

The local #1405 fix rejects the missing capture at definition time, even if the
generic function is never called. The corrected `[copy, id]` form has executable
coverage for both empty and nonempty tails. Ownership sign-off remains blocked
by #1407; the reduced symbolic-row reconstruction warning below is fixed locally.
This is not
a completed integration pass.

<!-- doc-example: expect-fail reason="An explicit capture list must include id; baseline incorrectly deferred T0026 to an I0010" -->
```metel
type Callback := once || -> i64;
fun invoke(f: Callback) -> i64 { f() }

fun transition<row R: !{token}>(r: { ..R }) -> { token: String, ..R } {
    { ..r, token = "secret" }
}

fun copied_tail<row R: !{token}>(r: { id: i64, ..R }) -> i64 where all R: Copy {
    let { id, ..rest } := r;
    let copy := rest;
    let callback := [copy] once || {
        let extended := transition(copy);
        let { token, ..again } := extended;
        id + token.len() as i64
    };
    invoke(callback)
}

fun main() {
    assert(copied_tail({ id = 3, count = 7 }) == 9);
    assert(copied_tail({ id = 5 }) == 11);
}
```

regressions also require a move violation when the field-wise `Copy` bound is absent.

### F02 — Empty nominal residual cannot be restored after parameter rebinding

Expected: the brand supplies the declared field types, and assigning both missing
fields reconstructs `Pair`. Actual, with and without move checking: `T0001`
at the function tail, saying a partially moved `Pair.{}` cannot satisfy `Pair`.
The direct local restoration in `empty_residual_checked.mtl` passes; the
parameter/rebinding case does not. An aliased empty residual captured by a
written `once || -> Pair` callback also fails with `T0001`; the unaliased
capture variant instead reports `T0002` on field assignment. These variants
need triage without assuming one root cause for every diagnostic. The local #1406
fix now restores initial absence state on residual bindings. Parameter rebinding
and aliased/written callback variants have executable coverage under move
checking, with missing-field and wrong-type negative guards.

The regression includes both a transparent `Pair.{}` alias and a transparent
callback-type alias. A direct locally emptied capture is a separate ownership
finding: `[pair] once var || -> Pair { pair.left := "new";
pair.right := "back"; pair }` executes without move checking but is rejected
at capture with `T0019` when ownership checking is enabled. The capture collector
encounters an assignment target first, records no use-site type for it, and falls
back to the original whole binding type rather than its current residual. The
ordinary `[pair] once ||` spelling correctly requires `var` for writes (`T0028`).
The direct mutable-capture case is separately tracked as
[#1409](https://github.com/metel-lang/metel-core/issues/1409), dependent on #1406.
Its local fix carries owned source entry types into ownership analysis; the
executable regression now restores empty and partial nominal captures under
move checking. Negative fixtures retain missing-field/incomplete-restoration
errors and whole-source move checks, including shadowed and unused generic
captures. This does not resolve the report's other ownership-audit limitations
or complete its release sign-off.

```metel
struct Pair { left: String, right: String }
fun rebuild(empty: Pair.{}) -> Pair {
    var restored := empty;
    restored.left := "new";
    restored.right := "back";
    restored
}
fun main() {
    let p := Pair { left = "old", right = "gone" };
    let left := p.left;
    let right := p.right;
    let restored := rebuild(p);
    assert(restored.left == "new");
}
```

### F03 — Equation-derived rest destructuring reports its own consumption as reuse

Existing fixture:
`evaluator/records/equation_derived_remainder.mtl`.
Its first function is:

```text
fun strip<row R, row Rest>(d: { ..R }) -> { ..Rest }
where R = { token: String, ..Rest } {
    let { token: _, ..rest } := d;
    rest
}
```

The checked-in fixture executes successfully without ownership enforcement.
Forcing `--move-check` reports `T0019` on line 3, column 33: `d` is used after
being moved at that very same line and column. This is the single consumption
that should distribute fields to the owned remainder, not a subsequent use.
The full `move-check-count` audit aborts with its corresponding invariant
assertion: `checker bug: move site reported as its own use for d`.
Consequently neither a final generic-skip count nor a negative-fixture-only
violation inventory was obtained; the baseline-of-18 gate is **not verified**.

The local #1407 fix gives record patterns sole ownership of place consumption.
The fixture now runs with move checking enabled, including empty and non-`Copy`
remainders, mutable bindings and chained equations. Its three by-value `Box`
method calls use independent receivers rather than reusing a moved one. Field
discard and #1405's full row/callback fixture also run with ownership checks;
a separate negative fixture retains `T0019` for genuine later source reuse.
