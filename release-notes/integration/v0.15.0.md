## Findings

All six were found by probing a pair, then re-run against a v0.14.1 binary to separate regressions from older
gaps. Each is filed in Backlog.

- **#1761** — an unsuffixed integer literal assigned to a `u8` field, an array element, or an enum variant
  field is stored as `i64`, so the next operation is `I0001`. Present in v0.14.1. Deferred to Backlog, but it
  is in the area this release's #1482 reworked (a literal must fit its type) and a reader of the changelog
  would expect those literals to behave; the language owner may want it in the release.
- **#1762** — `T0026` when a closure with a capture list calls a local `fun`. Present in v0.14.1. Deferred.
- **#1763** — `root::Type::method()` is `T0003`. Present in v0.14.1. Deferred.
- **#1764** — `--move-check` reports `I0011` for a generic body that uses `?` (`Option` and `Result`).
  Present in v0.14.1 for `Result`. Deferred.
- **#1766** — `--move-check` fails on a body that calls a closure with an open-record parameter (`I0001` for
  an implicit row, `I0011` for a declared `record R`). The implicit-row form is present in v0.14.1. Deferred.
- **#1767** — `--move-check` reports `I0011` for a module-qualified static method call in a generic body. New
  with #1683 (v0.14.1 rejected the program). Deferred.

Not findings: `{ ..p, r = 1 }` is rejected ("record spread already contains field") by design until RFC-0191
is decided, and `Option` still has no `==` (`T0005`), so fixtures compare through `match`.
