## Findings

The first pass found six defects, all fixed in metel-core#1773 with a fix for each class of defect, not only the
reported case. The second pass found one more.

- **#1761** (a literal stored to a narrow place keeps its `i64` runtime type): fixed. The fix reaches fields,
  elements, tuple slots, enum variant fields and `f32`, in concrete bodies.
- **#1762** (`T0026` for a local `fun` named in a closure with a capture list): fixed, including at run time,
  in generic functions and through nested closures.
- **#1763** (`root::Type::method()` was `T0003`): fixed for `root::`, `self::` and `super::` before a type
  name, for static methods, struct literals and variants; a type path that closes a module cycle is the
  circular-dependency error.
- **#1764** (`?` in a generic body under `--move-check`): fixed for `Option` and for a `Result` whose error type
  matches. A `From` conversion is #1770 (v0.16.0).
- **#1766** (a closure with an open-record parameter called under `--move-check`) and **#1749** (a call to a
  nested generic function): fixed. The same work fixed a defect the pass found underneath: a local binding that
  shadowed an outer generic function of the same name was typed against the outer scheme, so a wrong call
  was accepted and failed at run time.
- **#1767** (a qualified static method in a generic body): fixed, with a `Copy` field read out of a temporary.
  A non-`Copy` field is #1771 (v0.16.0).
- **New, #1774** — an unsuffixed literal in a **generic body** keeps no narrow type and is not range-checked:
  `a[0] := 250` for `[u8; 2]` fails with an internal error inside `fun go<T: Copy>`, and `a[0] := 300` is
  accepted. The cause is #1704: a generic body is reconstructed with no inference facts, so #1761's and #1482's
  checks have nothing to read. Not a regression (v0.14.1 behaves the same for the type; #1482's range check
  never reached generic bodies), but it is the same feature as two items in this release's changelog. Filed in
  the v0.15.0 milestone for the language owner to keep or move.

Filed to v0.16.0 along the way: #1769 (a `root::` path to an unimported module depends on import order), #1770,
#1771, #1772 (a struct or variant literal through a module prefix needs a glob import). #1751 is unrelated and
still open.

Not findings: `{ ..p, r = 1 }` is rejected by design until RFC-0191 is decided, and `Option` still has no `==`
(`T0005`), so fixtures compare through `match`.
