## Findings

None is a regression: each reproduces identically on the released v0.14.0 binary. None is soundness.
Under the bug policy they are filed to Backlog and do not block the release.

- **#1615** — a block-local `struct`/`record`/`enum` does not shadow a same-named module-level,
  imported or `std::core` type, contrary to `spec.declarations.variables.scoping-and-shadowing.legality-1`
  and `modules.md`. `severity:incorrect`. Deferred to Backlog.
- **#1616** — `std::core::Result::Ok { .. }` in an expression resolves to the module's own `Result` when it
  declares one. The #1587 changelog entry says the expression form "already worked"; that holds only
  when nothing shadows the name. `severity:incorrect`. Deferred to Backlog.
- **#1618** — the #1483 record diff covers a structural record type but not a named `record`, which
  still prints `cannot unify { x: ?1 } with P`. The changelog entry for #1483 overstates the fix.
  `severity:diagnostic`. Deferred to Backlog.

## Release type

The milestone and `ROADMAP.md` type v0.14.1 as a patch: "no accepted programs change", with the
exceptions #1587 and #1588 recorded on 2026-10-25. The `## v0.14.1` changelog section also contains
changes to which programs are accepted that are not recorded as exceptions:

- **previously accepted, now rejected:** `T0037` duplicate top-level names (#1560), `T0038`
  reserved intrinsic type names (#1582), `T0034` extended to aspect impls and aspects (#1229);
- **previously rejected, now accepted:** block-local enums (#1557), generic block-local types
  (#1556), struct patterns on block-local structs (#1565), types named after an inner block ends
  (#1561), a local `let` shadowing a module function (#1578), and the aliased core variants
  already recorded (#1588).

This is not a test failure, so it does not change the verdict; it is a release-type decision for the
language owner: record the exceptions on the milestone, or cut the release under a minor number.
