## Interaction matrix

This is the first release gated by the persistent registry. Coverage is computed: a pair has evidence when a
fixture cites a rule of each feature in its `spec = [...]` tags. A Tier A pair shares a subsystem, a Tier B pair
has adjacent subsystems, and a Tier C pair is everything else. The gate fails on an open Tier A cell in a new
feature's row.

```
Feature matrix for v0.16.0
Milestone-only baseline: 24 features · 276 pairs · evidence in 175 pairs (3 complete, 172 partial) · no evidence: 101 · mean rule coverage: 23.1%
Baseline Tier A open gaps: 0 · Tier A/B open gaps: 17
Release gate scope: 2124 new-vs-registry pairs · Tier A/B pairs: 613 · Tier A open (blocking): 0 · Tier A partial (reported): 136 · Tier A bulk-deferred: 125
Registry: 101 features · 0 without spec rule IDs · 0 unresolved introduction releases
Gate: PASS (0 open Tier A cells need a fixture, an n/a reason or a deferral issue)
```

- **The release's own features.** At the start of the session 19 Tier A pairs among the 24 features had no
  joint fixture. Three combined fixtures closed all of them, and the baseline now has 0 open Tier A cells. The 17
  open Tier A/B cells are Tier B pairs, which are reported and never gate.
- **New features against older ones.** 125 Tier A pairs of a v0.16.0 feature with an older feature have no
  fixture yet. They are bulk-deferred to metel-core#2086 (v0.16.1) by one `[[bulk]]` entry in
  `tools/feature-matrix/states.toml`. A cell leaves the deferral as soon as a fixture covers it. There are no
  hand-set `n/a` cells.
- **Partial cells.** 136 Tier A cells have partial rule coverage. They are reported and do not block.
- **Blocking rows.** None: `python3 tools/feature_matrix.py v0.16.0 --blockers` lists no open Tier A cell.

The coverage measure is the share of the two features' rules that joint fixtures cite. It does not judge the
quality of a fixture, and the registry maps some features to few rules, so a high score is not strong evidence.

## Fixtures added

Twenty-six new fixtures, all of which pass:

- 15 in `evaluator/integration/` (`v0_16_0_*`): copy function values in records, tuples and spreads; a residual
  holding a copy function; spreads over copy structs and tuples; tuple match exhaustiveness; named record
  patterns with nested patterns in generic bodies; copy-argument structs in closures and residuals; row bounds
  over flow structs; keyword calls in closures in a generic body; a block-local impl with spreads and tuples; and
  the three combined fixtures that closed the Tier A gaps (generic closures with
  clone, copy, keywords and assignment; generic record patterns with exhaustiveness, spreads and tuples; dotted
  labels with negative bounds, tuples and block-local impls).
- 9 in `typechecking/move_check/` (`v0_16_0_*`): seven T0047 fixtures (a `dyn` in a tuple, record, residual,
  spread, closure capture, a `copy(T)` struct, and a copy function beside an undecided `dyn`), one T0041 (a
  keyword argument through a function value), and one T0003 guard that a non-`Copy` generic struct still moves
  out of a tuple.
- 2 in `evaluator/move_check/` (`clone_of_a_copy_struct_holding_a_copy_function`,
  `clone_of_a_copy_function_field_copies_its_state`), the regression fixtures for #2078.

## Findings

- **#2078** — cloning a `Copy` struct that holds a `copy |T| -> U` field failed with `I0001`. Fixed on #2081.
- **#2079** — reading a generic `Copy` struct with an unresolved integer-literal argument twice from a tuple or
  record failed with `T0003`: the move check treated `Boxed<{integer}>` as undecided. Fixed on #2087; a type
  whose only free variables are unsuffixed numeric literals is now judged with the literals' default type.
- **#2085** — in a generic body, the result of calling an inferred closure, bound by an unannotated `let`, was
  typed `()` and `r + 1` failed with `I0010`. Reconstruction at a call carries no Pass 1 facts, so the closure's
  return type is now read off its body. Fixed on #2087.
- **#2086** — the 125 Tier A new-versus-old pairs above. Deferred to v0.16.1; the entry in `states.toml` is
  removed when the sweep is done.
- **Fixture tags and spec prose.** Re-reviewing the 34 rules whose citing fixtures changed found seven
  fixtures that cited rules they did not exercise (fixed on #2088) and three rules whose prose lagged the
  compiler (`declaration-clauses.legality-15`, `copy.legality-2`, `narrowing.legality-1`, amended on
  metel-docs#693). `rfc.py check --strict` is clean after it.
- Whether #2079 and #2085 are regressions is unknown: the v0.15.0 release binary needs glibc 2.39 and does
  not run on the integration host. Both were milestoned v0.16.0.
