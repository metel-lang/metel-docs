## Interaction matrix

This is the first release gated by the persistent registry (`tools/feature-matrix/registry.toml`, ADR-0069).
Coverage is computed: a pair has evidence when a fixture cites a rule of each feature in its `spec = [...]` tags.
A Tier A pair shares a subsystem, a Tier B pair has adjacent subsystems, and a Tier C pair is everything else.

The gate fails on any of: an open Tier A cell of a new feature; a Tier A pair among the release's own features
with fewer than two joint fixtures; an open Tier B pair among them; a new feature with evidence in under half of
its Tier A pairs; a bulk deferral of an earlier minor release that still has open cells. Partial coverage is
reported and never blocks. Under those rules v0.16.0 first failed with 40 violations (18 joint-fixture, 17 Tier B,
5 feature-floor); five combined fixtures and the corrected Display rules closed them.

The coverage measure is the share of the two features' rules that joint fixtures cite. It does not judge the
quality of a fixture, and the registry maps some features to few rules, so a high score is not strong evidence.
Citing a rule is a claim that the fixture exercises it, which the script cannot check; the re-review in this
session found seven fixtures that cited rules they did not exercise.

## Fixtures added

Thirty-one new fixtures, all of which pass:

- 19 in `evaluator/integration/` (`v0_16_0_*`): copy function values in records, tuples and spreads; a residual
  holding a copy function; spreads over copy structs and tuples; tuple match exhaustiveness; named record
  patterns with nested patterns in generic bodies; copy-argument structs in closures and residuals; row bounds
  over flow structs; keyword calls in closures in a generic body; a block-local impl with spreads and tuples; the

  clone, copy, keywords and assignment; generic record patterns with exhaustiveness, spreads and tuples; dotted
  labels with negative bounds, tuples and block-local impls); and the four that satisfy the stricter gate
  (super-aspects, negative impls and bounds, conditional impls, associated types and `dyn`; keyword calls and
  assignments in capture lists and mutating closures; Display, Clone, copy declarations and exhaustive matches;
  spreads, dotted labels, negative bounds and copy flows).
- 9 in `typechecking/move_check/` (`v0_16_0_*`): seven T0047 fixtures (a `dyn` in a tuple, record, residual,
  spread, closure capture, a `copy(T)` struct, and a copy function beside an undecided `dyn`), one T0041 (a
  keyword argument through a function value), and one T0003 guard that a non-`Copy` generic struct still moves
  out of a tuple.
- 1 multi-file fixture in `evaluator/structs/` (`v0_16_0_module_qualified_struct_literal_naming_a_private_field_is_t0009`).
- 2 in `evaluator/move_check/` (`clone_of_a_copy_struct_holding_a_copy_function`,
  `clone_of_a_copy_function_field_copies_its_state`), the regression fixtures for #2078.

## Findings

- **#2078** — cloning a `Copy` struct that holds a `copy |T| -> U` field failed with `I0001`. Fixed on #2081.
- **#2079** — reading a generic `Copy` struct with an unresolved integer-literal argument twice from a tuple or
  record failed with `T0003`: the move check treated `Boxed<{integer}>` as undecided. Fixed on #2087; a type
  whose only free variables are unsuffixed numeric literals is now judged with the literals' default type.
- **#2085** — in a generic body, the result of calling an inferred closure, bound by an unannotated `let`, was
  typed `()` and `r + 1` failed with `I0010`. Reconstruction at a call carries no Pass 1 facts, so the closure's
  return type is now read off its body. Fixed on #2087.
- **#2090** — under `--move-check`, a match over a tuple scrutinee in a generic body fails with `I0011` (the body is
  not analysed). Found writing the stricter-gate fixtures; it affects only `--move-check`, which is off by default.
  Deferred to v0.16.1. It has no fixture: the corpus completeness test fails on any unanalysed generic body.
- **#2086** — the 82 Tier A new-versus-old pairs above. Deferred to v0.16.1; the entry in `states.toml` expires
  at v0.17.0 and is removed when the sweep is done.
- **Fixture tags and spec prose.** Re-reviewing the 34 rules whose citing fixtures changed found seven
  fixtures that cited rules they did not exercise (fixed on #2088) and three rules whose prose lagged the
  compiler (`declaration-clauses.legality-15`, `copy.legality-2`, `narrowing.legality-1`, amended on
  metel-docs#693). `rfc.py check --strict` is clean after it.
- Whether #2079 and #2085 are regressions is unknown: the v0.15.0 release binary needs glibc 2.39 and does
  not run on the integration host. Both were milestoned v0.16.0.
